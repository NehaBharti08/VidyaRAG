\chapter{Reproducing Every Workflow}
\label{ch:reproducibility}

\enquote{A number in the README that cannot be traced back to one of these files is not evidence} \ev{src/vidyarag/evaluation/runner.py:14-16}. This chapter examines how far that standard is met: what is pinned, which workflows were re-run during this analysis and with what result, and where reproduction stops being exact.

\section{Three levels of reproducibility}

\begin{center}
\begin{tabularx}{\textwidth}{@{}>{\raggedright\arraybackslash}p{4.4cm}>{\raggedright\arraybackslash}p{3.0cm}L@{}}
\toprule
\textbf{Level} & \textbf{Achievable?} & \textbf{Why}\\
\midrule
Recompute every reported number from the committed run files & Yes, exactly & The files store per-question ids, scores, tokens and latencies\\
Rebuild the corpus and index from scratch & Yes; counts match & Deterministic parsing and chunking from checksummed PDFs\\
Re-run an evaluation and get the same numbers & Only the deterministic parts & Generation and model-judged metrics vary between runs\\
\bottomrule
\end{tabularx}
\end{center}

\section{What pins what}

\begin{longtable}{@{}>{\raggedright\arraybackslash}p{3.2cm}>{\raggedright\arraybackslash}p{6.4cm}>{\raggedright\arraybackslash}p{6.2cm}@{}}
\toprule
\textbf{Ingredient} & \textbf{Pinned by} & \textbf{Gap}\\
\midrule
\endhead
Code & The git commit & A run file does not record the commit that produced it\\
Dependencies & \code{uv.lock}, installed with \code{--frozen} in CI and Docker & The Space resolves ranges at build time; base images and the uv image use floating tags\\
Python & 3.10--3.12 supported; runs record their version & ---\\
Corpus bytes & SHA-256, size and page count in \code{data/raw/manifest.json} & Checksums are recorded, not compared with a previous manifest or a publisher digest\\
Parsing and chunking & Deterministic code; chunk ids derived from content position & ---\\
Embedding model & Model name in the configuration, the ingest report and every run file & The downloaded model files are identified only by name; no revision or file hash is recorded\\
Index & \code{data/ingest_run.json}; deterministic point ids & The report path is shared by every build (Section~\ref{sec:finding-ingest-report})\\
Gemini models & Exact model ids, never aliases & The provider can change behaviour behind an id; nothing records a model revision\\
Prompts & \code{answer-v1} in traces, run files and the cache key & The grader, decomposition and judge prompts are not versioned\\
Configuration & The full merged profile is saved in each run file & ---\\
Gold set & SHA-256 prefix in each run file; all five runs share \code{258cb6f9b1a2ab04} & ---\\
Gold-set tooling & Seeds \code{20260813} (drafting) and \code{20260816} (unanswerable) & Drafting temperatures of 0.7 and 0.9 mean re-drafting will not reproduce the questions\\

\section{Workflows re-run during this analysis}

\subsection{Environment and tests}

\begin{measured}
\code{uv run pytest -m "not costly" --cov} on the analysed commit: 401 passed, 1 skipped, 3 deselected; coverage 64.24\%. CI on the same commit passed on Python 3.10 and 3.11.
\end{measured}

\subsection{Corpus and index}

\begin{lstlisting}[language=bash]
uv run vidyarag download                        # re-hash the PDFs; compare with the manifest
QDRANT_PATH=<scratch folder> QDRANT_COLLECTION=vidyarag_verify_v1 \
  uv run vidyarag ingest --recreate             # rebuild into a throwaway index
\end{lstlisting}

\begin{measured}
Both PDFs re-validated: \emph{Biology} 1,480 pages, 279\,MB, SHA-256 beginning \code{723dec671a4d}; \emph{Anatomy and Physiology} 1,420 pages, 135\,MB, \code{16cb34457cba}. The rebuild took 1,944 seconds and produced 1,765 and 1,843 chunks --- 3,608 points, the same as the working index. Only the counts were compared; chunk texts and vectors were not compared point by point. The README records the same verification on 13 September.
\end{measured}

\begin{caution}
Running \code{ingest} into a scratch location still writes \code{data/ingest_run.json}, replacing the working index's run report. Copy the file first if you want to keep it.
\end{caution}

\subsection{The results tables}

\begin{measured}
Every aggregate in the committed run files was recomputed from their per-question data, including per-type retrieval and RAGAS means, rerank movement, decomposition split rates, corrective decisions and like-for-like comparisons. All matched the aggregates in the files, and the README table matches the files. \code{vidyarag report} regenerates the README table from them.
\end{measured}

\subsection{Abstention, re-scored}

\begin{measured}
The stored answers of all five runs were re-judged with the repository's abstention prompt and model, changing only the output budget from 5 to 50 tokens (Section~\ref{sec:res-corrective}). This needs a Gemini key and no regeneration, because the answers are in the run files.
\end{measured}

\subsection{The live behaviours}

\begin{measured}
The three behaviours the demo is built to show --- a cited answer, an abstention, an injection block --- were reproduced on the live Space and locally. A full \code{guarded} query was traced end to end (Chapter~\ref{ch:trace}).
\end{measured}

\section{Where exact reproduction stops}

\begin{description}[style=nextline]
  \item[Generation is not deterministic at temperature 0.] The repository measured three identical calls returning 315, 300 and 307 characters. During this analysis, the same prompt produced 130 output tokens in one run and 156 in another.
  \item[Model-judged metrics move.] The same baseline profile run twice moved answer relevancy by 0.043, according to \code{docs/EVALUATION.md} and the commit that introduced the noise measurement \ev{git 0f95a26}; the earlier of those two runs is not committed.
  \item[Abstention decisions move.] \code{corrective} and \code{guarded} --- functionally the same pipeline on this traffic --- refused 12 and 11 of the 12 unanswerable questions, and different answerable questions.
  \item[Providers fail transiently.] Two of three grading calls in this analysis returned 503 before one succeeded. In the self-check profiles, a failed grading call changes the outcome path (Section~\ref{sec:trace-failopen}).
  \item[Caches carry history.] The committed \code{guarded} run's answers were all served from an earlier generation pass; \code{decompose} reused 47. A re-run without that cache regenerates answers and will differ.
  \item[Timings depend on the machine.] The same rerank took 2.1 or 14.9 seconds on the same laptop at different times (Chapter~\ref{ch:performance}).
  \item[Some documented numbers have no committed source.] The baseline section of \code{docs/EVALUATION.md} quotes a run (\code{20260818T075845Z}) with faithfulness 0.954, relevancy 0.798 and 2,485\,ms mean latency; the commit that introduced the harness quotes the same figures \ev{git f8c8e35}. The committed baseline file is a later run, with 0.948, 0.755 and 1,091\,ms, and that is the one the README uses.
\end{description}

\section{A reproducibility checklist for future runs}

\begin{recommended}
\begin{enumerate}
  \item Record the git commit, the machine and whether each answer was cached in every run file.
  \item Record model file hashes for fastembed models, and a model version or response metadata for Gemini where available.
  \item Version the grader, decomposition and judge prompts as the answer prompt already is.
  \item Include every answer-changing setting in the answer-cache key, or key it on a hash of the whole configuration.
  \item Run each profile at least three times and report the spread, especially for abstention.
  \item Store per-stage timings, exclude a warm-up question, and report medians.
  \item Commit every run that a document quotes.
  \item Write the ingest report beside the index it describes.
\end{enumerate}
\end{recommended}
