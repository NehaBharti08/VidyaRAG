\chapter{Architecture}
\label{ch:architecture}

VidyaRAG is one Python package, \code{vidyarag}, under \code{src/vidyarag}. It has no microservices, no queue and no relational database. It has three user-facing entry points --- a CLI, a FastAPI app and a Gradio page --- that all call the same \code{Pipeline} object. It uses one vector store (Qdrant) and two model sources: local ONNX models via fastembed for embedding and reranking, and Google Gemini for generation, grading and decomposition. Behaviour lives in committed YAML profiles, and evidence lives in committed result files.

\section{Ingestion}
\label{sec:arch-ingest}

Ingestion turns two PDFs into a searchable index, offline and without an API key. It is driven by \code{vidyarag download} and then \code{vidyarag ingest} (Figure~\ref{fig:arch-ingest}). It has four properties worth stating:
\begin{itemize}
  \item \textbf{Idempotent.} Point ids are \code{uuid5(namespace, chunk_id)}, so writing a chunk twice overwrites it instead of duplicating it \ev{src/vidyarag/store/collection.py}.
  \item \textbf{Resumable.} The orchestrator first reads back which chunk ids already exist and embeds only the rest \ev{src/vidyarag/ingest/pipeline.py}.
  \item \textbf{Credential-free.} Nothing on this path imports the Gemini SDK.
  \item \textbf{Provenance.} A manifest records the PDFs' checksums and page counts. A per-collection run report, \code{data/ingest_run.<collection>.json}, records the model, the chunking parameters and the counts.
\end{itemize}

\section{Query time}
\label{sec:arch-query}

Every entry point calls \code{Pipeline.answer(question)}. The active \emph{profile} decides which stages run; the code path is the same. Figure~\ref{fig:arch-query} shows the shipped \code{guarded} profile. Its key properties:
\begin{itemize}
  \item \textbf{Flags, not code paths.} Reranking, decomposition, the self-check and both guards are booleans read inside one \code{Pipeline} class, and a hermetic test asserts that each flag really changes what runs \ev{tests/test_query_pipeline.py}.
  \item \textbf{Cheap refusals first.} The input guard runs before any embedding, search or model call. A blocked question returns \code{blocked=True} and \code{grounded=False}.
  \item \textbf{Retrieval is local.} Only generation and grading reach the network.
  \item \textbf{A retry re-retrieves.} It reruns the whole retrieval chain with a reformulated query, rather than only re-asking the generator.
  \item \textbf{The trace travels with the answer.} Each \code{Answer} carries a \code{QueryTrace} (wall clock, nested stage timings, tokens by purpose) and a \code{SelfCheck} state.
  \item \textbf{One pipeline per process.} Embedded Qdrant locks its folder, so the API builds the pipeline once at startup and the demo keeps a module-level singleton.
\end{itemize}

\section{Evaluation and deployment}
\label{sec:arch-eval}

\paragraph{Evaluation} (\code{vidyarag eval}) runs in two phases on purpose \ev{src/vidyarag/evaluation/runner.py}. \emph{Generation} is sequential, because the embedded index cannot be opened concurrently. It paces calls 4\,s apart, makes up to three attempts on transient errors, and caches every answer under a key that hashes the whole configuration. \emph{Grading} is concurrent and rate-limited. It covers the abstention judge and the four RAGAS metrics, reached through Google's OpenAI-compatible endpoint. The deterministic retrieval metrics are computed in between, with no model call. The result is a JSON run file plus a rendered Markdown report in \code{eval/results/}. The separate \code{vidyarag rejudge} command rebuilds the abstention verdicts of committed runs from their stored answers, without spending any generation quota.

\paragraph{Deployment.} Pushing to GitHub runs CI (lint, types and tests on Python 3.10 and 3.11, plus a secret scan) and a Docker workflow that builds the API image, runs it, waits for it to become healthy and calls it. \emph{Nothing deploys automatically.} The Hugging Face Space is updated only by running \code{scripts/deploy_space.py} by hand, which uploads a 61-file, 35\,MB payload that includes the index. The image is never pushed to a registry (Chapter~\ref{ch:shipping}).

\section{Properties worth being able to state}

\begin{enumerate}
  \item \textbf{Two swap points.} Qdrant access lives only in \code{store/client.py}, and model construction only in \code{llm/provider.py}. The swap was exercised once, when the stack moved from OpenAI to local embeddings plus Gemini.
  \item \textbf{Configuration is reviewed data.} A profile fully describes a variant and is committed; secrets never live in one.
  \item \textbf{The index ships with the demo.} The Space carries its own 35\,MB index, so no free-tier database can expire and take the demo down.
  \item \textbf{Retrieval has no third-party runtime dependency.} Only answering does.
  \item \textbf{Everything measurable is returned per query,} not merely logged.
\end{enumerate}
