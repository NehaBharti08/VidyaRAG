The package is 9,290 lines. It uses the \emph{src layout}, so it is importable only once installed (\code{uv sync}) or put on \code{sys.path}, which is what the Space bootstrap does. Evaluation code lives in \code{vidyarag.evaluation} rather than a top-level \code{eval} package, which would shadow Python's built-in \code{eval}. \code{.gitignore} keeps out the PDFs (large, and reproducible from a checksummed manifest), the index (shipped through the Space's own repository), \code{.env} and caches. It commits \code{eval/results/*.json} on purpose: ``the run history is the evidence behind the README results table''.

Python 3.10 is the floor because ZeroGPU images are pinned to it and ignore the Space's \code{python_version} \ev{pyproject.toml}. Two 3.11 features had crept into the code (\code{enum.StrEnum} and \code{datetime.UTC}) and once stopped the Space from starting. They now go through \code{_compat.py}, whose backport sets \code{__str__ = str.__str__}. Without that line, \code{QdrantMode.EMBEDDED} would format as \code{QdrantMode.EMBEDDED} on 3.10, \enquote{the one that silently corrupts output rather than raising.} CI runs the full suite on 3.10 so that this claim is tested. \textbf{No GPU is used anywhere.} The Space runs on ZeroGPU only because the platform requires a GPU-decorated function to exist at startup; the app declares one and never calls it \ev{app/app.py}.

\paragraph{What it does not use.} Searching every import found no PyTorch, TensorFlow, \code{transformers}, SQL or Redis, and no cloud SDKs, experiment trackers, queues, authentication libraries, \code{tiktoken} or \code{numpy} in project code. \textbf{There is no LLM framework.} LlamaIndex was declared, advertised and never imported, and was then removed. LangChain appears only as a dependency of RAGAS. The pipeline is written directly against \code{qdrant-client}, \code{fastembed} and \code{google-genai}.

\section{Dependencies}

Runtime dependencies (14 packages) are in \code{[project] dependencies}. The \code{dev} (9) and \code{eval} (5) groups are separate, and \code{uv.lock} pins everything; CI and Docker install with \code{--frozen}. Four constraints look odd and are deliberate:
\begin{itemize}
  \item \textbf{The eval group stays out of the image.} RAGAS pulls in LangChain, about 200\,MB (stated, not measured), ``for code that never runs in production''.
  \item \textbf{\code{langchain-community<0.4}} is an upstream bug pin. RAGAS 0.4 imports a module that 0.4.0 removed, so \code{import ragas} would fail outright.
  \item \textbf{The Space pins major versions, not exact ones}, because ``a hard pin that stops resolving turns a working demo into a build failure months later.'' It omits Gradio entirely: declaring a range alongside the builder's own pin once failed with \code{ResolutionImpossible}.
  \item \textbf{Pre-commit hooks match the lockfile}: black 25.12.0, ruff 0.16.0, mypy 1.20.2. They did not before the fixes. The hooks then ran black 24 while the project used black 25, and each rewrote the other's output.
\end{itemize}
Three disagreements remain. Gradio is installed in the API image, which never imports it. \code{pandas} and \code{datasets} are declared and never imported. And \code{huggingface_hub} is imported by the deploy script but only arrives transitively.

\label{sec:config}

\paragraph{\code{Settings}.} \code{GOOGLE_API_KEY} is stored as a \code{SecretStr}, so it never appears in \code{repr} or logs, and a test asserts this. It is not needed to download, ingest or search. \code{QDRANT_MODE} is \code{embedded}, \code{server} or \code{cloud}. The model validator requires \code{QDRANT_URL} for server and cloud and \code{QDRANT_API_KEY} for cloud, so a missing URL fails at startup rather than deep inside a query. \code{QDRANT_PATH} defaults to \code{data/index} and is resolved against the repository root; \code{:memory:} gives a throwaway index. \code{QDRANT_COLLECTION} defaults to \code{vidyarag_biology_v1}. \code{VIDYARAG_PROFILE} defaults to \code{guarded}. It used to be \code{baseline}, which meant a fresh clone ran with the guardrails down. \code{LOG_LEVEL} and \code{LOG_FORMAT} are read by the API only.

\paragraph{Path traps.} \code{.env} is found relative to the \emph{working directory}. Run the CLI from elsewhere and the key is simply empty: retrieval works, and the first Gemini call fails \tagI. \code{REPO_ROOT} is \code{Path(__file__).parents[2]}, which is wrong after a non-editable install. The Docker image once refused to start with \enquote{Unknown profile 'guarded'. Available: (none)}, so it sets \code{VIDYARAG_CONFIG_DIR=/app/config} and an absolute \code{QDRANT_PATH}.

\paragraph{The five profiles.} Each changes flags only; models, temperature, chunking, top-$k$ and thresholds are identical across all five.

The \code{baseline} file says \enquote{DO NOT EDIT IT. Changing it silently invalidates every reported delta}, and a test asserts that every enhancement stays off. \code{rerank} states its own sanity check: pool recall must not change. \code{decompose} keeps the reranker off because ``running both would leave that unattributable.''

\paragraph{Loading.} \code{load_pipeline_config} resolves the directory (an argument, else \code{VIDYARAG_CONFIG_DIR}, else \code{<repo>/config}). It then deep-merges the profile onto \code{default.yaml}: nested mappings merge key by key, and everything else replaces. Last, it validates the result. Mistakes therefore surface at startup: an unknown profile lists the available ones, a misspelt key is a \code{ValidationError}, \code{use_hybrid: true} is rejected as ``reserved but not implemented'', and inverted thresholds are rejected. That last check used to happen only at the first corrective query.

\paragraph{Dead keys.} Three keys are read by no code: \code{embedding_max_tokens}, \code{chunking.respect_sentence_boundaries} and \code{retrieval.sparse_model}. Only the last is documented as reserved. The 512 limit holds only because \code{chunk_size} is also 512.

uv run vidyarag config --profile guarded      # merged config, incl. guards + thresholds
uv run vidyarag ask "What is osmosis?" --profile rerank
QDRANT_MODE=server QDRANT_URL=http://localhost:6333 uv run vidyarag health
\end{lstlisting}
