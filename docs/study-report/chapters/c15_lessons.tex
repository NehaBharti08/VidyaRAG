\section{The bug that invalidated the headline}
\label{sec:judge-bug}

This is the most useful story in the project, because it is about \emph{evaluation integrity}: the evaluation lied, in the direction everyone expected, and nothing objected.

\paragraph{The claim.} The published headline result was ``abstention recall $0.000 \rightarrow 0.917$--$1.000$'': the baseline never refused, and the self-check taught the system to. It appeared in the README, \code{docs/EVALUATION.md}, the \code{corrective} profile, the loop's docstring, the Space README and several commit messages.

\paragraph{The mechanism.} Abstention on free text is decided by a model asked to reply with one word, \code{REFUSED} or \code{ANSWERED}. It was called with \code{max_tokens=5}, and the reply was tested with \code{startswith("REFUSED")}.

\begin{measured}[the same prompt and answer at three budgets, against the live endpoint]
\begin{center}\small
\begin{tabular}{@{}rlll@{}}
\toprule
\code{max_tokens} & content & \code{finish_reason} & read as\\
\midrule
5 (shipped) & \code{'REF'} & \code{length} & \textbf{not a refusal}\\
16 & \code{'REFUSED'} & \code{stop} & a refusal\\
50 & \code{'REFUSED'} & \code{stop} & a refusal\\
\bottomrule
\end{tabular}
\end{center}
The label was truncated mid-word. The function returned \code{False} for \emph{every} input, including the pipeline's own canonical abstention sentence. All 275 cached verdicts were ``not abstained''.
\end{measured}

\paragraph{Why nobody noticed.} The history shows the developer knew half of it. On 28 August a commit records that ``the generator can already refuse on its own'', and adds the \code{refuses} flag so that the loop would not take credit for those refusals. The \emph{other} side of the comparison went unchecked: whether the baseline's prose refusals were being counted. They were not, so the baseline read 0.000 --- the \emph{expected} value for a pipeline ``with no corrective loop'', described in \code{EVALUATION.md} as ``the single most useful number in this table.'' A wrong number that confirms the design is the hardest kind to see. It also lived behind a network call, so no test ever compared the judge's output with a known label.

\paragraph{How it was found.} The analysis read the stored answers instead of the aggregates. The baseline's answers to all 12 unanswerable questions were refusals: ``The provided passages do not contain information comparing the ATP turnover in a hummingbird to a human\ldots'' Twelve refusals scored as zero meant the instrument, not the system, was wrong. The three-budget measurement above then confirmed the mechanism.

\paragraph{The fix} \ev{src/vidyarag/evaluation/abstention.py}:
\begin{enumerate}
  \item A 64-token budget, and the label matched as a whole word, with the last match winning.
  \item Parsing moved into a pure function, \code{parse_judge_label}, tested without a network against \code{'REF'}, \code{'REFUSED'}, empty text and prose.
  \item A truncated, empty, unparseable or failed judgement is now \code{unmeasured}, never ``answered''. A judge whose failures all land on one label does not produce a noisy metric; it produces a confident wrong one.
  \item Each run file records how each verdict was reached, and the aggregate reports the unmeasured count.
  \item A judge version enters the verdict-cache key, or the fixed judge would keep reading the broken one's verdicts off disk.
\end{enumerate}

\paragraph{The re-measurement.} \code{vidyarag rejudge} rebuilds verdicts from the stored answers, spending no generation quota. Two independent implementations --- the analysis's throwaway script and the new command --- agree cell for cell. The corrected result is in Section~\ref{sec:results}: recall is 1.000 for four profiles and 0.917 for the shipped one. The self-check makes refusals structured; it does not make them more frequent.

\paragraph{A second bug, found by fixing the first.} The first re-judging pass ran too fast, and 30 calls hit 429. Those failures were written to the verdict cache \emph{as verdicts}, and the next run read them back and never retried --- a transient rate limit turned into a permanent hole in the metric. That is the same shape as the original bug, one layer down: a failure quietly becoming a number. Now only measured verdicts are cached. The 30 poisoned entries were removed and re-judged, and the two \code{guarded} questions still hitting quota are reported as \code{unmeasured}.

\paragraph{The retraction.} The README now explains the old figure rather than quietly replacing it, and a test fails if ``0.000'' reappears in its abstention row. The docstrings, the profile comment and \code{DESIGN.md} were corrected. \code{EVALUATION.md}, a dated phase-by-phase record, keeps its original text with ``Retracted'' notes and an erratum table. Its reasoning (``0.000 is the expected behaviour'') is precisely the lesson.

\section{What was checked and found to be right}

A findings list can suggest nothing works. These were verified directly. Citations cannot point outside the supplied passages. The corpus pipeline is reproducible: 3,608 chunks from a scratch rebuild. The deterministic retrieval metrics are correct and read the right lists, and the reranking and decomposition results are real. The guards produce no false positives on the corpus. Every number in the README table matches a committed file. CI and the Docker workflow are green. The demo's three behaviours work live, and secrets hygiene holds. And the documentation was already unusually candid: it recorded decomposition's failure, the quality gains that were not real, the untuned thresholds and the definitional-question weakness. \textbf{All 485 file-and-line citations in the original 257-page audit resolved to real code, and every table in it recomputed exactly from the run files.}
