\chapter{Testing}
\label{ch:testing}

The repository has 28 test modules and a shared fixture file, 4,066 lines in total. This chapter explains how the suite is built, what it proves, what it cannot see, and which tests would have caught the defects in Chapter~\ref{ch:findings}.

\section{Strategy: hermetic by default}

The default suite never touches the network, a paid model, a Qdrant server or the real corpus:

\begin{itemize}
  \item \textbf{No credentials.} An autouse fixture deletes \code{GOOGLE_API_KEY}, every \code{QDRANT_*} variable, \code{VIDYARAG_PROFILE}, \code{LOG_LEVEL} and \code{LOG_FORMAT} before each test, so a developer's \code{.env} cannot leak in \ev{tests/conftest.py:21-38}. CI provides no real key.
  \item \textbf{In-process Qdrant.} The \code{memory_settings} fixture builds \code{Settings} with no dotenv file, a fake key, \code{:memory:} storage, a \code{test_collection} and the \code{baseline} profile \ev{tests/conftest.py:42-52}.
  \item \textbf{Synthetic PDFs.} Parser tests \enquote{build small PDFs in-process rather than shipping fixture files}, using PyMuPDF to create pages and insert text \ev{tests/test\_parse.py:3-35}.
  \item \textbf{Mocked HTTP.} Download tests use respx to simulate full downloads, partial content, ignored range headers and stale partial files.
  \item \textbf{Fake models.} Embeddings are stubbed and language-model clients are small fake objects, so no model is downloaded in CI \ev{git 9ccd6c2}.
  \item \textbf{Live tests are opt-in.} Three tests in \code{tests/test_live_pipeline.py} carry the \code{costly} marker, are deselected by \code{-m "not costly"} everywhere, and skip themselves if no key or index is available.
\end{itemize}

pytest runs with \code{-ra --strict-markers --strict-config} and \code{asyncio_mode = "auto"}; two markers are registered, \code{costly} (3 tests) and \code{integration} (none) \ev{pyproject.toml:193-208}.

\begin{measured}[the suite on the analysed commit]
\code{pytest -m "not costly" --cov}: \textbf{401 passed, 1 skipped, 3 deselected} in 72 seconds; \textbf{coverage 64.24\%} of 3,029 statements and 626 branches, above the 60\% floor. The skipped test is \code{tests/test_eval_preflight.py:46}, which only runs when the evaluation dependency group is \emph{absent}; its counterpart runs when the group is present.
\end{measured}

\section{Techniques worth recognising}

\begin{description}[style=nextline]
  \item[Tests named as specifications.] A failing test's name states the broken promise, for example \code{test_exhausting_the_budget_abstains_rather_than_shipping_the_draft}.
  \item[Incidents become regression tests.] The three cardiovascular headings, the 39-of-58 incident run, the smoke run in the evidence directory and the pre-check ordering all have tests.
  \item[Contracts over non-Python files.] Tests read the Dockerfile, \code{pyproject.toml}, the README's Mermaid diagram, \code{docs/EVALUATION.md} and \code{.gitignore}, and fail when they drift from the code. The container contracts were confirmed to fail against the previous Dockerfile \ev{git 88d7969}.
  \item[Environment-aware assertions.] The dependency pre-check has one test for each state of the environment, after a version that assumed the developer's packages turned CI red \ev{git 4e09511}.
  \item[Deployment artefacts tested before deployment.] The generated Space \code{app.py} must compile and must not use Python 3.11-only names --- the two failures that once stopped the Space starting.
  \item[A small live layer.] Three end-to-end tests exist because \enquote{every bug that reached the deployed Space was invisible to the hermetic suite} (README).
\end{description}

\section{What the tests cannot see}

\begin{itemize}
  \item \textbf{Behaviour of real models.} Fakes return whatever a test chooses. The abstention judge's truncation (F1) could only appear with a real response --- or with a test that feeds it one.
  \item \textbf{Whole-trace invariants.} No test checks that a trace's total equals elapsed time (F3), or that every model call records usage (F4).
  \item \textbf{How failures are presented.} Nothing checks what the API or demo show when grading fails (F5), and the demo has no tests at all.
  \item \textbf{Pipeline integration without the network}, as the coverage gaps above show (F6).
  \item \textbf{API promises}: \code{book_slug} on \code{/v1/query} (F10) and the meaning of \code{grounded} for blocked questions (F11).
  \item \textbf{The CLI and gold-set drafting} (0\% coverage), concurrency, load, and adversarial inputs beyond the hand-written guard cases.
\end{itemize}
