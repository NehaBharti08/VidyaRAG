\chapter{Complete Local Setup on a Fresh Machine}
\label{ch:setup}

This chapter takes a machine with nothing installed to a working local VidyaRAG: index built, questions answered, API and demo running, tests passing. Commands are given for a Unix-like shell; where Windows PowerShell differs, the difference is shown.

\section{What you need}

\begin{center}
\begin{tabularx}{\textwidth}{@{}>{\raggedright\arraybackslash}p{3.3cm}L@{}}
\toprule
\textbf{Requirement} & \textbf{Details}\\
\midrule
Operating system & Developed on Windows 11; CI and Docker use Linux. macOS is not exercised anywhere in the repository; whether it works is \NotDet\\
Python & 3.10 or 3.11 (the README says so, and CI tests both). uv can install it for you.\\
uv & Required: every command runs through \code{uv run}. The analysis used uv 0.12.2.\\
Git & To clone the repository.\\
Disk & About 415\,MB for the PDFs, 35\,MB for the index, and room for the virtual environment and the model downloads (the code puts the embedding model at about 210\,MB and the reranker at about 80\,MB).\\
Network & To download dependencies, the PDFs and the models once. Ingestion itself runs offline.\\
Gemini API key & Free, no card, from Google AI Studio. Needed only to answer questions and to evaluate; not needed to build the index.\\
Docker & Optional: only for the container or a local Qdrant server.\\
\bottomrule
\end{tabularx}
\end{center}

\section{Step by step}

\subsection{1. Clone and install}

\begin{lstlisting}[language=bash]
git clone https://github.com/NehaBharti08/VidyaRAG.git
cd VidyaRAG

# Install uv first if needed: https://docs.astral.sh/uv/
uv sync                    # runtime + dev tools, exactly as locked in uv.lock
uv sync --group eval       # add RAGAS etc. only if you will run evaluations
uv run pre-commit install  # optional: gitleaks, ruff, black, mypy on every commit
\end{lstlisting}

\subsection{2. Configure}

\begin{lstlisting}[language=bash]
cp .env.example .env                  # PowerShell: Copy-Item .env.example .env
# Edit .env and replace the placeholder:
#   GOOGLE_API_KEY=<your key from https://aistudio.google.com/apikey>
# Leave QDRANT_MODE=embedded, QDRANT_PATH=data/index and VIDYARAG_PROFILE=guarded.
\end{lstlisting}

\begin{caution}[two configuration traps]
\begin{enumerate}
  \item \textbf{Replace the placeholder key, do not leave it.} The example value is not empty, so the \enquote{no API key} check will not fire; the first Gemini call will fail instead, with an authentication error from the API.
  \item \textbf{Run every command from the repository root.} \code{.env} is found relative to the current directory (Section~\ref{sec:config-paths}).
\end{enumerate}
\end{caution}

\subsection{3. Check the configuration}

\begin{lstlisting}[language=bash]
uv run vidyarag health
# OK    settings loaded (profile=guarded)
# OK    qdrant target: embedded (<repo>/data/index)
# OK    pipeline config valid
# OK    qdrant reachable (0 collection(s))
# WARN  collection 'vidyarag_biology_v1' not found - run ingestion first
uv run vidyarag config               # the merged guarded profile
\end{lstlisting}

The warning is expected before ingestion. The lines follow the messages in \code{cli.py} \ev{src/vidyarag/cli.py:274-322}.

\subsection{4. Build the index}

\begin{lstlisting}[language=bash]
uv run vidyarag download             # about 415 MB, resumable, writes data/raw/manifest.json
uv run vidyarag ingest               # parse, chunk, embed, store; about 32 minutes on the analysis machine
uv run vidyarag health               # should now report 3608 points
\end{lstlisting}

Ingestion can be interrupted and restarted; it skips passages already stored. Use \code{--recreate} to rebuild from scratch.

\subsection{5. Ask questions}

\begin{lstlisting}[language=bash]
uv run vidyarag ask "How does facilitated diffusion move glucose into a cell?"
uv run vidyarag ask "What is osmosis?" --context            # also print the passages
uv run vidyarag ask "What is osmosis?" --profile baseline   # a different pipeline
\end{lstlisting}

The first question in each process is slow while the models load (between about 5 and 24 seconds on the analysis machine), and slower still the very first time, while they download.

\subsection{6. Run the API and the demo}

\begin{lstlisting}[language=bash]
uv run uvicorn vidyarag.api.main:app        # http://localhost:8000/docs
curl http://localhost:8000/v1/health
curl -X POST http://localhost:8000/v1/query -H "Content-Type: application/json" \
     -d '{"question": "What happens during anaphase of mitosis?"}'
curl -X POST http://localhost:8000/v1/search -H "Content-Type: application/json" \
     -d '{"query": "cell membrane structure", "top_k": 3}'

uv run python app/app.py                    # Gradio demo on http://localhost:7860
\end{lstlisting}

\begin{caution}[one process at a time]
The embedded index can be open in only one process. Stop the API or the demo before running \code{ingest}, \code{ask}, \code{health} or \code{eval} against the same \code{data/index}.
\end{caution}

\subsection{7. Run the tests}

\begin{lstlisting}[language=bash]
uv run pytest -m "not costly"                               # hermetic suite
uv run pytest -m "not costly" --cov --cov-report=term-missing
uv run pytest -m costly                                     # 3 live tests: needs key and index
uv run ruff check . && uv run black --check . && uv run mypy # what CI runs besides the tests
\end{lstlisting}

\begin{measured}[expected result]
On the analysed commit: 401 passed, 1 skipped, 3 deselected, in 72 seconds; coverage 64.24\%, above the 60\% floor. The skipped test is the one that can only run when the evaluation group is \emph{not} installed.
\end{measured}

\subsection{8. Optional: evaluate}

\begin{lstlisting}[language=bash]
uv sync --group eval
uv run vidyarag eval --profile guarded --limit 4    # smoke run into eval/results/scratch/
uv run vidyarag eval --profile guarded              # full run: tens of minutes on the free tier
uv run vidyarag report
\end{lstlisting}

\subsection{9. Optional: Docker}

\begin{lstlisting}[language=bash]
docker build -t vidyarag .
docker run -p 8000:8000 -v "$(pwd)/data/index:/app/data/index" -e GOOGLE_API_KEY=<key> vidyarag

docker compose up -d                                 # a local Qdrant server instead
QDRANT_MODE=server QDRANT_URL=http://localhost:6333 uv run vidyarag health
\end{lstlisting}

The mount must be writable, because embedded Qdrant takes a lock file inside it \ev{Dockerfile:75-87}. A server-mode collection starts empty and must be ingested into.

\section{Troubleshooting}

\begin{longtable}{@{}>{\raggedright\arraybackslash}p{5.4cm}>{\raggedright\arraybackslash}p{4.8cm}>{\raggedright\arraybackslash}p{5.6cm}@{}}
\toprule
\textbf{Symptom} & \textbf{Cause} & \textbf{Fix}\\
\midrule
\endhead
\code{GOOGLE_API_KEY is not set} & No key, or \code{.env} not found & Add the key; run from the repository root\\
Authentication error on the first answer & Placeholder key left in \code{.env} & Paste a real key\\
\code{Unknown profile '...' in <dir>} & Misspelt profile, or a wrong \code{VIDYARAG_CONFIG_DIR} & Use one of the listed profiles\\
\enquote{already accessed by another instance of Qdrant client} & Another process has the index open & Stop the API, demo or other command\\
\code{collection ... not found - run ingestion first} & No index yet, or another collection name & Run \code{download} and \code{ingest}\\
\code{Collection ... has N-dim vectors} & Embedding model changed & \code{vidyarag ingest --recreate}\\
\code{grading needs the 'eval' dependency group} & RAGAS or OpenAI client missing & \code{uv sync --group eval}\\
HTTP 429 or 503 from Gemini & Free-tier limits or provider load & Wait and retry; lower \code{--rate} for evaluations\\
First answer very slow & Models downloading or loading & Expected once per process\\
\code{make} targets fail on Windows & They use Unix tools & Run the \code{uv run ...} command directly, or use Git Bash\\
\code{uv sync} changes \code{uv.lock} & Dependency edits & Use \code{uv sync --frozen} to install exactly what is locked\\
\bottomrule
\end{longtable}
