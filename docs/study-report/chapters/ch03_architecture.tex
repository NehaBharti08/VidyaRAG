\chapter{Architecture}
\label{ch:architecture}

This chapter describes the architecture \emph{as implemented}, reconstructed by reading every module and tracing imports and calls. It is organised around the three activities from Chapter~\ref{ch:plain} --- preparing the index, answering questions, and measuring --- plus how the pieces are deployed.

\section{The big picture}

VidyaRAG is a single Python package, \code{vidyarag}, located at \code{src/vidyarag}. There are no microservices, no message queues and no relational database. The moving parts are:

\begin{itemize}
  \item \textbf{One Python package} containing every stage of the pipeline.
  \item \textbf{Three user-facing entry points} that all call the same pipeline object: a command-line tool (\code{src/vidyarag/cli.py}), an HTTP API (\code{src/vidyarag/api/}), and a Gradio web page (\code{app/app.py}).
  \item \textbf{One vector store}: Qdrant, reached through a single factory function.
  \item \textbf{Two model sources}: local ONNX models via fastembed (embedding and reranking) and Google Gemini via the \code{google-genai} SDK (generation, grading, decomposition, gold-set tooling); evaluation additionally reaches Gemini through Google's OpenAI-compatible endpoint.
  \item \textbf{Committed configuration and evidence}: YAML profiles under \code{config/}, a gold set and result files under \code{eval/}.
\end{itemize}

\paragraph{Key properties (all verified in code).}
\begin{itemize}
  \item \textbf{Idempotent}: point ids are \code{uuid5(POINT_NAMESPACE, chunk_id)}, so writing a chunk twice overwrites it instead of duplicating it \ev{src/vidyarag/store/collection.py:25-43}.
  \item \textbf{Resumable}: before embedding, the orchestrator scrolls the collection for chunk ids that already exist and embeds only the rest \ev{src/vidyarag/ingest/pipeline.py:159-176}.
  \item \textbf{Credential-free}: nothing in this path imports the Gemini SDK \ev{src/vidyarag/llm/provider.py:109-129}.
  \item \textbf{Provenance}: a manifest records checksums and page counts of the PDFs, and a run report records the model, chunking parameters and counts \ev{src/vidyarag/ingest/download.py:199-221}, \ev{src/vidyarag/ingest/pipeline.py:65-84}.
\end{itemize}

\paragraph{Key properties (verified).}
\begin{itemize}
  \item \textbf{Flags, not code paths.} Reranking, decomposition, the corrective loop and both guards are switched by booleans in the profile, read inside the one \code{Pipeline} class \ev{src/vidyarag/pipeline.py:84-193}.
  \item \textbf{Cheap refusals first.} The input guard runs before any embedding, search or model call \ev{src/vidyarag/pipeline.py:155-171}.
  \item \textbf{Retrieval is local.} Embedding and reranking run on CPU with no network after model download; only generation and grading reach Gemini.
  \item \textbf{A retry re-retrieves.} On a retry the loop calls the whole retrieval chain again with a reformulated query, not merely the generator \ev{src/vidyarag/correct/loop.py:141-166}.
  \item \textbf{The trace travels with the answer.} Every \code{Answer} carries a \code{QueryTrace} with stage timings, token usage and what each guard or loop did \ev{src/vidyarag/pipeline.py:34-48}.
  \item \textbf{One shared pipeline per process.} Embedded Qdrant locks its folder, so the API builds the pipeline once at startup and the Gradio app keeps a module-level singleton \ev{src/vidyarag/api/main.py:30-50}, \ev{app/app.py:68-92}.
\end{itemize}

\section{Architectural properties worth being able to state}

\begin{enumerate}
  \item \textbf{Two single swap points.} Qdrant access lives only in \code{store/client.py}; model construction lives only in \code{llm/provider.py}. The package documentation notes that this swap point was already exercised once when the stack moved from OpenAI to local embeddings plus Gemini \ev{src/vidyarag/llm/__init__.py:1-6}.
  \item \textbf{Configuration is code-reviewed data.} A profile fully describes a pipeline variant and is committed; secrets never live in profiles \ev{src/vidyarag/settings.py:1-14}.
  \item \textbf{The index ships with the demo.} The deployed Space carries its own 35\,MB index instead of calling a hosted vector store, so no free-tier database can expire and take the demo down \ev{scripts/deploy_space.py:7-12}.
  \item \textbf{Retrieval has no third-party runtime dependency}; only answering does.
  \item \textbf{Everything measurable is recorded per query} and returned to the caller rather than only logged \ev{src/vidyarag/observe/trace.py:1-15}.
\end{enumerate}
