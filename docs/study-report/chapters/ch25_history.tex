\chapter{Problems Met During Development, and How They Were Fixed}
\label{ch:history}

The repository's git history is unusually informative: most commit messages explain the problem, how it was found, the fix and why the fix is right. This chapter reconstructs the development story from those 31 commits, the code comments that record incidents, and the tests written to stop each problem returning. Quotations are from commit messages unless another source is cited.

\section{Problem by problem}

Each entry follows the brief's format. \emph{Problem}, \emph{root cause}, \emph{identification} and \emph{fix} are taken from commit messages, code comments and the code itself; \emph{why the fix works} and \emph{alternatives} add explanation.

\begin{description}[style=nextline,itemsep=1pt,topsep=2pt]
  \item[Problem] #1
  \item[Root cause] #2
  \item[How it was identified] #3
  \item[Fix] #4
  \item[Why the fix works] #5
  \item[Alternatives] #6
\end{description}}

\subsection{The corpus licence was wrong}
\vrprob{\code{ATTRIBUTION.md} said \emph{Biology 2e} and \emph{Microbiology} were CC BY 4.0, supported by a quoted preface.}{The licence was inferred from the title, but OpenStax relicensed many second editions as CC BY-NC-SA 4.0.}{Querying OpenStax's content API, which returned the NonCommercial-ShareAlike licence \ev{git 85d4f8b}.}{Switch to the first editions of \emph{Biology} and \emph{Anatomy and Physiology}, verify each edition through the API, record UUIDs and ISBNs, and replace the invented preface quote with the verification command.}{The publisher's API is the authoritative record, and checking per edition removes the ambiguity that caused the error.}{Keep the second editions and accept NonCommercial terms, which would restrict reuse of an MIT-licensed repository; or use another publisher's books.}

\subsection{Chunks were silently truncated at embedding time}
\vrprob{Full-size chunks lost their final sentences when embedded, with no error.}{Chunks were sized with a tiktoken tokenizer, but \code{bge-base-en-v1.5} counts WordPiece tokens --- about 7\% more on this prose --- and truncates at 512, so a \enquote{512-token} chunk was about 548 model tokens.}{While indexing the corpus for real in Phase 1b \ev{git 9ccd6c2}.}{Measure chunk size with the embedding model's own tokenizer (\code{count_tokens} in \code{llm/provider.py}).}{The budget is now counted in the same units in which the model truncates; after the fix the largest chunk was 487 tokens.}{Leave headroom (for example 450 tiktoken tokens), which is fragile and wastes context; or embed overlapping windows and pool them.}

\subsection{Tests destroyed the real index's provenance}
\vrprob{Running the test suite overwrote \code{data/ingest_run.json}.}{\code{ingest()} always wrote its report to one fixed path.}{Noticed while running ingestion for real \ev{git 9ccd6c2}.}{The report path became a parameter, and tests pass their own.}{Tests no longer share a file with the developer's working data.}{Use a temporary \code{REPO_ROOT} in tests. \textbf{The CLI still writes to the fixed path}, which is how this analysis overwrote the same file (Section~\ref{sec:finding-ingest-report}).}

\subsection{Grouped citations disappeared}
\vrprob{An answer supported by five passages showed only two references.}{The marker pattern matched \code{[1]} but not \code{[1, 2]}, which Gemini writes at least as often.}{Running the real pipeline, not a unit test \ev{git dac78a2}.}{Match grouped and semicolon forms; prune invalid numbers inside a group rather than dropping it.}{Every marker form the model uses now resolves, and a partly invalid group keeps its valid references.}{Instruct the model to write only \code{[1][2]}, which it would not reliably follow.}

\subsection{A broken run printed a flattering table}
\vrprob{An evaluation that lost 39 of 58 questions to quota exhaustion still reported metrics, with faithfulness 0.949.}{Averages were computed over whatever survived; the gold set is ordered by type, so the survivors were 17 factual, no multi-hop and 2 unanswerable questions.}{Inspecting the failed run \ev{git f8c8e35}.}{\code{MAX_FAILURE_RATE = 0.10}: above it, the report withholds every metric and lists failures by type.}{A partial run is \enquote{a confident measurement of a different, easier thing}; refusing to print it removes the temptation to quote it.}{Weight or impute missing questions, which would invent data; or shuffle the gold set, which would only hide the bias.}

\subsection{An evaluation hung with no output and no error}
\vrprob{A run stopped after 18 of 58 questions and printed nothing.}{Answering was unpaced, hit a per-minute limit, and then waited inside the SDK's internal retry loop without a timeout.}{The stalled run \ev{src/vidyarag/evaluation/runner.py:85-95}.}{A 4-second gap between live generation calls, and a 90-second timeout on every Gemini request.}{Pacing avoids the limit; the timeout turns an invisible hang into a visible, retryable error.}{Exponential back-off on 429 alone would still hang without a timeout.}

\subsection{Fifty minutes of grading lost to a spinner}
\vrprob{\code{vidyarag eval > log.txt} crashed with \code{UnicodeEncodeError} after fifty minutes.}{Redirected output on Windows uses code page 1252, which cannot encode Rich's spinner characters.}{The crash \ev{src/vidyarag/cli.py:43-54}.}{Reconfigure stdout and stderr to UTF-8 at start-up; omit the spinner when output is not a terminal.}{The failing characters can now always be encoded, and never appear in logs.}{Set \code{PYTHONIOENCODING} in documentation, which users forget.}

\subsection{RAGAS would not run with Gemini}
\vrprob{\code{import ragas} failed; once imported, every metric raised \enquote{Cannot use agenerate() with a synchronous client}.}{RAGAS 0.4 imports a module removed from \code{langchain-community} 0.4.0, and it detects asynchronous clients by an OpenAI-specific attribute.}{The failures themselves; the upstream issues are cited in \code{pyproject.toml}.}{Pin \code{langchain-community<0.4}; drive RAGAS with \code{AsyncOpenAI} pointed at Google's OpenAI-compatible endpoint.}{The pin restores the import; the endpoint satisfies RAGAS's detection while still calling Gemini.}{Write the metrics by hand, rejected as weaker evidence \ev{docs/DESIGN.md}; or use a different model provider that needs billing.}

\subsection{Retrieval metrics could not see the reranker}
\vrprob{After adding reranking, context recall and MRR were bit-identical to the baseline while context precision moved six points.}{Every retrieval metric was computed from the pre-rerank candidate list.}{The impossible combination of an unchanged MRR and a moved precision \ev{src/vidyarag/evaluation/retrieval.py:108-111}.}{Score pool recall from the candidates, MRR from the final ordering and context recall from the passages in the prompt; compute these outside the answer cache.}{Each metric now reads the list that its definition refers to.}{Store only the final context, which would lose the pool-versus-context distinction.}

\subsection{The generator's own refusals would have been credited to the loop}
\vrprob{On a real unanswerable question, the draft said \enquote{the provided passages do not contain information comparing\ldots}, scored 1.0, was accepted, and the loop reported \code{abstained=False}.}{A statement that the passages lack something is fully supported by passages that lack it, so claim scores cannot distinguish a refusal from a good answer.}{A smoke test of the corrective loop \ev{git 6539036}.}{The grader also returns \code{refuses}; the policy abstains whenever it is true.}{The refusal is detected directly instead of through its score.}{Keyword matching on phrases like \enquote{do not contain}, which is brittle.}

The commit message states the risk precisely: without the flag, \enquote{this project would have credited a corrective loop for refusals the generator produced by itself.} Section~\ref{sec:history-lesson} returns to this.

\subsection{The injection guard fired on the cardiovascular chapters}
\vrprob{An earlier context pattern matched three real passages.}{A bare \code{SYSTEM:} at the start of a line matched \enquote{THE CARDIOVASCULAR SYSTEM: BLOOD} and two similar headings, wrapped by PDF extraction.}{Running the patterns over all 3,608 passages \ev{git 08fde04}.}{Require directive language after the role marker on the same line; add the three headings as regression tests.}{Real injections issue orders; headings do not.}{Maintain an allow-list of headings, which would not generalise.}

\subsection{An unanswerable question set that could be gamed}
\vrprob{Of 12 machine-proposed unanswerable questions, 11 contained \enquote{exact} and 9 began \enquote{What is the exact\ldots}.}{An unguided prompt collapses onto one template.}{Reading the proposals \ev{git 07b0791}, \ev{src/vidyarag/evaluation/verify.py}.}{Rotate eight question shapes, forbid the giveaway words, and reject candidates with cosine similarity of 0.88 or more to an accepted one.}{A system can no longer score abstention by recognising a phrasing.}{Write the questions by hand, the original plan, which the design notes rejected as a review too large to happen \ev{docs/DESIGN.md}.}

\subsection{A declared, documented framework that was never used}
\vrprob{The README named LlamaIndex as the orchestration layer and justified the choice.}{It was in the plan and the dependency list, and was never imported.}{\enquote{found by checking whether the claim was true, not by anything failing} \ev{git 8fa9478}.}{Remove it from the dependencies, the Space requirements and the mypy overrides; state that there is no framework.}{The documentation now describes the code.}{Keep it and use it somewhere, which would add indirection for appearances.}

The same commit contains a note about a résumé bullet that mentions LlamaIndex; Chapter~\ref{ch:resume} covers how to handle it.

\subsection{The \enquote{shipped} column described another configuration}
\vrprob{The README's \enquote{shipped} results used the \code{corrective} run, but the demo, container and deploy script run \code{guarded}, which had never been evaluated.}{The guards were added after the evaluation, and the table was not updated.}{Checking which profile each deployment uses \ev{git 84703dd}.}{Evaluate \code{guarded}; report ranges where the two runs differ.}{The table now reflects the deployed configuration, and the ranges expose run-to-run variance (abstention recall 1.000 in one run, 0.917 in the other).}{Quote only the better run, which the commit explicitly rejects.}

\section{Patterns the history names}

The commit messages identify recurring shapes themselves:

\begin{itemize}
  \item \textbf{\enquote{Cheap knowledge arriving after expensive work}} --- a missing dependency discovered after generation, a missing secret after an hour of indexing, metrics unable to see a component after a full run \ev{git ca86450}.
  \item \textbf{\enquote{A check that consults the ambient environment instead of declaring what it needs}} --- the pre-commit mypy hook missing \code{typer}, a test passing only because of leftover packages \ev{git 4e09511}.
  \item \textbf{Claims checked against reality} --- LlamaIndex, \code{tenacity}, the corpus size, the markers, the threshold sweep: each found \enquote{by checking whether the claim was true}.
  \item \textbf{\enquote{Every bug that reached the deployed Space was invisible to the hermetic suite}} --- the README's own justification for the live tests.
\end{itemize}

\section{What the history says about the abstention claim}
\label{sec:history-lesson}

\begin{verified}[the sequence, in the project's own words]
\begin{enumerate}
  \item 18 August: \enquote{Abstention recall is zero because the baseline has no corrective loop and cannot decline} \ev{git f8c8e35}.
  \item 28 August: \enquote{The generator can already refuse on its own \ldots{} this project would have credited a corrective loop for refusals the generator produced by itself} \ev{git 6539036}.
  \item 28 August, same commit: \enquote{Baseline abstention recall is 0.000 across every Phase 4 profile: the pipeline answered all twelve unanswerable questions because nothing in it could decline.}
  \item 29 August: \enquote{Abstention recall 0.000 -> 1.000} \ev{git b2d6954}.
\end{enumerate}
\end{verified}

\begin{inferred}
The second statement shows the developer knew the generator refuses in prose, and built the refusal flag so the loop would not take credit for it. What went unchecked was the other side of the comparison: whether the baseline's prose refusals were being counted. The truncated judge (Section~\ref{sec:judge-bug}) returned \enquote{answered} for all of them, so the baseline's 0.000 looked like confirmation rather than a symptom. The repository's usual method --- checking whether a claim is true --- was applied to many numbers, but not to this one, probably because it agreed with the design's expectation.
\end{inferred}
