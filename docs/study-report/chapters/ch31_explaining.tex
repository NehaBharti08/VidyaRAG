\chapter{Explaining the Project}
\label{ch:explaining}

This chapter gives ready-to-speak explanations at four lengths, a version for non-technical listeners, a whiteboard talk track, and how to adjust the emphasis for different roles. Every factual statement in them is verified elsewhere in this report; the wording itself is a recommendation.

\begin{caution}[before using these scripts]
Parts of the longer versions discuss defects found during this analysis. Only present them once you have checked the evidence yourself and can walk through it --- ideally after fixing them (Chapter~\ref{ch:improvements}). The shorter versions are accurate whether or not the fixes are made.
\end{caution}

\section{The 30-second version}

\begin{keyidea}[about 75 words]
VidyaRAG is a study assistant for biology that answers only from two open OpenStax textbooks and cites the printed page for each claim. Retrieval runs locally --- BGE embeddings in an embedded Qdrant index, reranked by a cross-encoder --- and Gemini writes the answer. A second Gemini model checks the draft claim by claim, and when the passages do not support an answer the system returns a fixed abstention instead of guessing. It is live on Hugging Face, with an evaluation harness behind every design decision.
\end{keyidea}

\section{The 1-minute version}

\begin{keyidea}[about 160 words]
A general chatbot gives you a fluent answer to a textbook question with no way to tell whether it came from the book or from nowhere. I built VidyaRAG so every answer is traceable: it retrieves from 3,608 passages of two open textbooks, the model must cite numbered passages, and citations that point at passages it was not given are stripped. A second model grades each claim; if the draft is a refusal or poorly supported, the system abstains with a fixed, citation-free message.

I treated it as an experiment. There is a frozen baseline, a 58-question gold set, and each component is ablated on its own. Reranking raised the share of gold passages reaching the prompt from 0.880 to 0.913 and MRR from 0.770 to 0.830 on an unchanged candidate pool. Query decomposition made multi-hop retrieval worse, so I rejected it. It ships as a FastAPI service, a CLI and a Gradio demo, with Docker built and health-checked in CI and 400-plus tests.
\end{keyidea}

\section{The 3-minute version}

\begin{enumerate}
  \item \textbf{Problem.} Students need answers they can check against the book. The design goal was that a RAG system should be able to prove an answer is in the source, and abstain when it is not.
  \item \textbf{Ingestion.} Two OpenStax first editions --- chosen because they are the only CC BY biology titles, checked per edition. The PDF outline gives real chapters and sections, printed page numbers come from the running heads, question sets and answer keys are removed, and text is packed into sentence-aligned chunks of at most 512 tokens counted with the embedding model's own tokenizer. Chunks are embedded locally on CPU and stored in Qdrant with deterministic ids, so re-ingestion is idempotent. Rebuilding from the PDFs reproduces the same 3,608 chunks.
  \item \textbf{Query path.} A regex guard screens the question before any work. Dense search returns 20 candidates; a MiniLM cross-encoder reorders them; the top 5 are screened for embedded directives and sent to Gemini with rules to use only those passages and cite each claim. Invalid citation markers are removed. A different Gemini model splits the draft into claims and marks each supported, partial or unsupported, and flags drafts that are refusals. The policy accepts, retries once with a query built from the failed claims, or abstains. Every answer carries a trace of stage timings, tokens and list price.
  \item \textbf{Evaluation.} Five profiles, each changing one thing from a frozen baseline. Retrieval metrics are computed from chunk ids --- exact and free --- alongside RAGAS and abstention precision, recall and false-abstention rate. Runs with more than 10\% failures report no metrics, because a partial run is a measurement of an easier question set.
  \item \textbf{Results.} Reranking: recall@context 0.880 to 0.913, MRR 0.770 to 0.830, pool recall unchanged. Decomposition: multi-hop context recall fell from 0.861 to 0.778, because rank fusion favours passages that several sub-questions agree on, which are the generic ones. The self-check did not make answers better on a like-for-like comparison; what it does is turn refusals into one explicit, citation-free, countable response, and its false abstentions trace back to retrieval misses.
  \item \textbf{What an audit of the measurements found.} The abstention judge was capped at five output tokens, so it could never return \enquote{refused}; the baseline had actually refused all 12 unanswerable questions in prose. The trace also double-counted time nested inside the self-check stage, and grading calls were not counted in tokens or cost. \emph{[Say what you fixed and re-measured.]}
  \item \textbf{Next.} Integration tests for every profile, per-term glossary chunks for definitional questions, diversity-aware context for multi-hop questions, and a larger gold set with repeated runs.
\end{enumerate}

\section{For a non-technical listener}

\begin{keyidea}[plain language]
I built a study helper that only answers from two free biology textbooks. When you ask a question, it finds the most relevant pages, writes an answer that points to those pages, and then has a second AI check each sentence against the pages. If the books do not contain the answer, it says so instead of making something up. I also built a way to measure whether each part actually helps, and dropped a part that made things worse.
\end{keyidea}

The bottom row is one question: \emph{question $\rightarrow$ guard $\rightarrow$ search 20 $\rightarrow$ rerank 5 $\rightarrow$ guard $\rightarrow$ generate with citations $\rightarrow$ grade $\rightarrow$ accept / retry / abstain}. Draw the retry arrow from \emph{grade} back to \emph{search}, labelled \enquote{query = question + failed claims}. Put a box beside both rows labelled \emph{evaluation: gold set $\rightarrow$ profiles $\rightarrow$ metrics}, with an arrow into every component. Narrate in that order; stop at each arrow to say what crosses it (text, 768 numbers, 20 ids, 5 passages, a draft, claims and verdicts).
